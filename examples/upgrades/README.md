# Upgrade and rollback review packets

These six bounded JSON packets were generated by the CLI from temporary copies of
[the three bootstrap profiles](../bootstrap-v2/README.md), with a deliberate
`build.rs` execution trap. Planning/reversal previews changed no consuming bytes;
apply, exact same-packet replay and separately reviewed reverse restored the
original snapshots. No repository build, hosted release or credential operation
ran. The packets carry their actual UTC review day and are examples, not approvals
for a different workspace. Generate and review a fresh packet for real use.

- `library`: actual v2 ownership migration; a bespoke appended job and owner policy
  comment remain exact. Reverse restores the prior v2 owner and deletes upgrade ownership.
- `cli`: unowned local setup creates the five catalog-backed targets. Reverse deletes
  those newly created files and upgrade ownership; empty directories may remain.
- `service`: supported v1 toolchain ownership migrates, with an explicitly imported
  compiled caller plus retained semantic-contract job. Reverse restores that v1
  owner and original caller bytes. No fabricated old catalog is qualified.

Schemas provide independent structural validation. Rust loaders additionally
reconstruct compiled authority, pin/compatibility displays, generated bases,
three-way decisions and exact reverse operation inventories. These proofs cover
local configuration/byte preservation, not signed provenance, hosted capabilities,
Apple finalization, publication, operational migration between two accepted
catalogs or full #5 acceptance. See [the operator guide](../../docs/upgrades.md).
